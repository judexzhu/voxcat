Analysis: etcd Memory Scaling

etcd stores all Kubernetes objects in a single bbolt database. Each namespace creates entries in multiple indices: namespace index, resource version index, and key-range index.

Key factors:
- Each namespace adds ~2-5KB of index overhead
- 500 namespaces = ~1-2.5MB additional index memory
- Watch caches multiply this by active watcher count
- HCP topology concentrates more objects per etcd instance

Recommendation: Scale etcd memory as: base (256Mi) + 2MB per 100 namespaces + 20% headroom.
